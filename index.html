How I build

From a requirements document to a live demo: the five steps I follow.

I

Requirements

Every project starts with a clear requirements document: who uses it, what they need and which rules must never break. I write down the scope before the first line of code, whether it's a web app, a tool or a model.

  • Requirements doc
  • Use cases
II

Data model

Screens come after the data. I design the relational model first and version it with migrations (EF Core Code First, SQL scripts), so every number in the app can be traced back to a record.

  • SQL Server
  • PostgreSQL
  • EF Core
III

Architecture & API

Clear boundaries between Domain, Application, Infrastructure and API layers, following Clean Architecture and SOLID. Related changes are saved together in one transaction, and each rule lives in exactly one place.

  • ASP.NET Core
  • Express
  • Clean Architecture
IV

Interface

Fast, responsive interfaces in React or ASP.NET MVC, and 3D scenes with three.js where they genuinely help people understand or decide.

  • React
  • TypeScript
  • three.js
V

Ship

Tests, a clean build and something you can open. Most of my projects run as live demos right in the browser on GitHub Pages; the rest ship as downloadable releases.

  • Tests
  • GitHub Pages
  • Releases
