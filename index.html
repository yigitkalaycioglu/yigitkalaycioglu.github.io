How I build

To begin, a requirements document. I write down who uses the thing, what they need and which rules must never break, before the first line of code. For the bookkeeping app the document also says what is out of scope.

Then the data. Screens come after the model. I design the relational schema, version it with migrations and calculate numbers from records instead of storing them: a balance is never saved, it is summed from the account movements.

After that, the boundaries. Domain, Application, Infrastructure and API stay separate, and each rule lives in exactly one place. The Clean Architecture Generator writes that structure for a new ASP.NET Core solution in one click.

Only then, the interface. Fast, plain screens in React or ASP.NET MVC, and 3D with three.js where it really helps someone understand or decide.

Finally, proof that it works. Every push runs the format check, unit tests and integration tests against a real SQL Server. Most projects end as a live demo you can open in the browser; the rest ship as releases.
